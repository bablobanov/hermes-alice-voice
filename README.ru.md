# Голосовой ввод Алисы для Hermes

[English](README.md) · [Участие](CONTRIBUTING.md) · [Безопасность](SECURITY.md)

**0.3.0 — только голосовой ввод, без патчей SDK Hermes.** Приватный навык Алисы передаёт распознанный текст в одну существующую личную Telegram-сессию Hermes. Ответ приходит в Telegram, а не озвучивается Алисой.

```text
Алиса → приватный навык → HTTPS → локальный плагин → штатный gateway → Telegram
```

«Запрос принят для обработки. Ответ будет в Telegram» означает лишь постановку на **асинхронную обработку**. Это не гарантия маршрутизации, завершения модели или доставки. «Ответ готов?» и «Дальше» напоминают проверить Telegram: чтения результата, callback завершения и Alice TTS нет.

## Статус и совместимость

Один оператор сообщил об успешной реальной цепочке голос → приватный навык → Hermes → Telegram. Это не проверка всех живых сценариев авторизации, повторов, сети и модели.

`requires_hermes: ">=0.21.3"` в манифесте — установочные метаданные, **не доказанный универсальный порог совместимости**. Конкретные три проверенные штатные исходника и их SHA-256 указаны в [английском README](README.md#status-and-compatibility). Используются обычный `inject_message`, фабрика подключения Telegram, unload и core estop. Другие ревизии требуют проверки. Изменения ядра не нужны и не поставляются.

## Установка

Нужны работающий Telegram gateway Hermes в **default-профиле**, уже созданная и авторизованная личная Telegram-сессия, приватный навык Алисы и HTTPS reverse proxy под вашим контролем. Плагин использует стандартную библиотеку Python; версию выбирайте по требованиям вашего Hermes. Актуальная модель доверия и разрешений — в [документации Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins).

1. Проверьте `plugins/alice-voice/__init__.py`, `bridge.py`, `plugin.yaml`. Скопируйте только эти три файла в `alice-voice` существующего каталога плагинов Hermes: обычно `$HERMES_HOME/plugins` или `~/.hermes/plugins` для default. Тесты устанавливать не нужно. Используйте свои обычные права и процесс проверки; не обходите ограничения вашей установки.
2. Локально создайте случайный секрет: `python3 -c 'import secrets; print(secrets.token_hex(32))'`. В `.env` Hermes (путь показывает `hermes config env-path`) задайте `ALICE_WEBHOOK_SECRET=<YOUR_64_HEX_RANDOM_SECRET>`, заменив placeholder сгенерированным значением. Не коммитьте секрет и не передавайте credentials в теле запроса Алисы. Ограничьте доступ к `.env` и настройкам навыка.
3. Добавьте в `config.yaml`, сохранив настройки других плагинов. Все placeholders замените своими значениями:

```yaml
plugins:
  enabled:
    - alice-voice
  entries:
    alice-voice:
      allow_gateway_injection: true
      settings:
        enabled: true
        skill_id: "<YOUR_PRIVATE_ALICE_SKILL_ID>"
        session_key: "agent:main:telegram:dm:<YOUR_TELEGRAM_USER_ID>"
        owner_user_id: "<YOUR_ALICE_ACCOUNT_USER_ID>"
        port: 8788
```

В `session_key` нужен положительный числовой ID существующей авторизованной личной Telegram-сессии. Маршрут задаёт оператор, не payload. `owner_user_id` необязателен: `""` допускает любой вошедший аккаунт с bearer и совпадающим skill ID — выбирайте это только осознанно. Placeholders секрета, навыка и сессии не активируют плагин.

4. Настройте свой HTTPS reverse proxy на точный путь `/alice/<YOUR_64_HEX_RANDOM_SECRET>` к loopback-порту плагина. В **приватном** навыке задайте соответствующий HTTPS webhook со своим доменом и секретом. URL не должен попадать в issues, скриншоты, историю shell, access logs или аналитику. Готового публичного адреса и конфигурации proxy здесь нет.
5. Перезапустите gateway обычным способом вашей установки. Импорт и регистрация плагина в CLI **не открывают порт**: listener запускается только при вызове gateway фабрики подключения Telegram, unload его закрывает. Bind — `127.0.0.1`, по умолчанию порт `8788`. Сначала создайте Telegram-сессию, затем проверьте безобидную голосовую задачу и отдельно её результат в Telegram.

## Безопасность и ограничения

- Для **одного оператора и приватного навыка**, не публичного многопользовательского сервиса. Секретный URL — bearer credential. **Подпись Яндекса не проверяется**. Skill/account ID из тела — проверка недоверенных утверждений, не криптографическая идентификация; владелец bearer может их подделать.
- Текст поступает как пользовательский ввод с правами фиксированной Hermes-сессии. Payload не меняет роль, модель, инструменты или адресата. Начальные slash-команды и управляющие символы запрещены, но обычная речь может просить вызвать инструменты. Сохраняйте штатные approvals и авторизацию gateway.
- Только default-профиль и Telegram DM. Core estop блокирует новые задачи; приветствие, помощь, выход и напоминания об ответе обрабатываются локально. Алиса не подтверждает действия и не управляет Hermes.
- Дедупликация: последние **32** принятых ключа, только в памяти. После вытеснения/рестарта защита исчезает; **exactly-once нет**. Асинхронная маршрутизация может отказать после ACK, повторный ACK не является квитанцией о доставке.
- До 4 096 символов на текстовое поле, тело до 16 384 байт, только JSON POST. Простой однопоточный HTTP-сервер: нет durable queue, общего rate limiter и HA. Используйте защищённый proxy с лимитами.
- Плагин не пишет HTTP request logs, но proxy, платформы, gateway, история сессий и провайдер модели имеют отдельные политики. Отключение/смена секрета требуют перезапуска gateway; после утечки смените секрет.

## Тесты

Из корня репозитория:

```sh
python -B -m unittest discover -s plugins/alice-voice -v
```

CI: Python 3.11/3.12/3.13, **11 bridge + 4 control tests**, синтетические ID и временные bearer. HTTP-проверки работают на временных loopback-портах без Telegram/Яндекса. Не заданный optional SDK test пропускается; skip не является успешной интеграцией.

Для проверенного checkout/runtime Hermes с установленными зависимостями:

```sh
ALICE_TEST_ENGINE_ROOT="<YOUR_HERMES_ENGINE_ROOT>" \
ALICE_TEST_ENGINE_PYTHON="<YOUR_HERMES_PYTHON_EXECUTABLE>" \
python -B -m unittest discover -s plugins/alice-voice -p test_sdk_http.py -v
```

Проверяются SHA **текущих** трёх файлов, затем SDK/gateway копируются во временный каталог. Неподдерживаемая версия/дерево даёт понятный `SkipTest`; ошибки зависимостей не маскируются успехом. Дочерний процесс получает очищенное окружение и временный Hermes home. Семь проверок штатных scheduling/dispatch/turn используют синтетические authorization, worker, store, transport и estop, **без реального LLM и доставки Telegram**. Backup-файлы не нужны и не восстанавливаются.
